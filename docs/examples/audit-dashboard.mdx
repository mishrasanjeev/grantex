## Overview

The example writes nine audit entries for two agents, reads them back with the
TypeScript SDK and prints a report:

1. **Two agents, two grants.** `data-reader` and `notifier` are registered and
   authorized for the same user.
2. **Known activity.** Six successful entries, two failures for actions outside
   the granted scopes, and one blocked entry.
3. **Timeline.** Both agents' entries, merged and sorted by time.
4. **Slices.** Each agent on its own, then only `email:send` with its metadata.
5. **Summary.** Outcome percentages, entries per agent, and action counts.
6. **Hash chain.** The developer's unfiltered entries are walked to confirm that
   each `prevHash` matches the previous entry's `hash`. The chain is kept per
   developer, which is why the check does not filter by agent.

## Prerequisites

- **Node.js 24 LTS**
- **Docker** with Compose

## Run

From the repository root, start the local stack:

```bash
docker compose up --build
```

Then, in another terminal:

```bash
cd examples/audit-dashboard
npm install
npm start
```

## Sample output

```text
=== Audit Trail Report ===

Registered data-reader: ag_01...
Registered notifier: ag_01...
Both agents authorized.

--- Recording activity ---
Recorded 9 entries (6 success, 2 failure, 1 blocked).

--- Timeline ---
   # Mark Outcome Agent          Action              Time (UTC)
   1 [+]  success data-reader    data:read           22:39:31
   ...
   8 [!]  blocked notifier       email:send          22:39:31
   9 [x]  failure data-reader    calendar:write      22:39:31

--- Summary ---
  Entries: 9
  success  6 (67%)
  failure  2 (22%)
  blocked  1 (11%)

--- Hash chain ---
  Intact: 9 linked entries

Report complete.
```

## Configuration

| Variable | Default | Meaning |
|----------|---------|---------|
| `GRANTEX_URL` | `http://localhost:3001` | Auth service base URL |
| `GRANTEX_API_KEY` | `sandbox-api-key-local` | API key; a sandbox key approves consent automatically, which the script relies on |
